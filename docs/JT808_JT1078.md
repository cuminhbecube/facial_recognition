# JT808 / JT1078 Integration

## Current status — firmware 0.6.1 source

The production platform is BECAM-2 with PR2100K dual AHD and EC800M-CN GNSS.
EC25 is a legacy modem profile. Location `0x0200` consumes the shared
`GnssManager` snapshot and does not depend on an EC25-specific class.

Remote snapshot capture is implemented through `0x8801` request parsing and
the asynchronous `0x0805` response path. Playback search/session support is
present in the current source; CMS visual playback remains a target-level
validation item. Multimedia upload is not part of the snapshot response path.

## Production Configuration

Edit through Web Config at `/jt808` or provision the mode-0600 file:

```text
/run/rv06-config/jt808.conf
```

The control endpoint and terminal identity come from CMSV6 provisioning. The
JT1078 media endpoint must not be added to this file because it is supplied by
CMSV6 message `0x9101` for each session.

The historical debug profile used `cam.tracking.vn:6608` and terminal phone
`874903786373`. Production identity is device-specific and follows the last 12
digits of the active modem IMEI; it is not derived from the RV1106 CPU serial.
Every production device must have its own terminal phone and terminal ID
registered in CMSV6; do not reuse an identity on another device.

Web Config `/jt808` documents every field. Numeric province/city IDs are
decimal `0-65535`; manufacturer ID is at most 5 ASCII characters, model at
most 20, terminal ID at most 7, and terminal phone at most 12 decimal digits.
Plate color follows JT808: `0` no plate, `1` blue, `2` yellow, `3` black, `4`
white, and `9` other.

`AUTH_MODE=REGISTER_RESPONSE` sends registration on every new control
connection, atomically stores the code from a successful `0x8100`, and sends it
in `0x0102`. `AUTH_MODE=STATIC` sends the provisioned `AUTH_CODE` directly.
Binary CMSV6 authentication values are stored internally as `HEX:<hex>` and
decoded before `0x0102`; Web Config never returns the value in clear.

## Video Mapping

```text
PR2100K VIN0 / VC0 / CAM0 -> VENC2 H.264 -> JT1078 logical channel 1
PR2100K VIN1 / VC1 / CAM1 -> VENC3 H.264 -> JT1078 logical channel 2
```

Both streams are hardware encoded H.264 Annex-B, configurable geometry (D1 / 360p default / CIF),
frame rate (5, 10, 12 default, 15 FPS), bitrate (200, 350, 500 default, 800, 1000 Kbps CBR),
Normal-P, video-only TCP. VENC0/VENC1 remain dedicated to H.265 recording.
RTSP sub-streams share VENC2/VENC3 seamlessly with JT1078 fanout.

The JT/T 1078 RTP-like fixed header uses `V=2`, `P=0`, `X=0`, `CC=1` (byte
`0x81`). Payload type is H.264 dynamic type 98. Marker `M` is set for an atomic
packet or the final fragment and cleared for first/middle fragments. This is
required for CMSV6 to recognize frame boundaries.

## Initial Scope

Supported: registration, authentication, common response, heartbeat, location,
real-time start/stop, H.264 video over TCP, both cameras, reconnect and bounded
backpressure.

DRV1 login/logout events are also reported to CMSV6 with the JT808-2013
driver identity message `0x0702`. Login maps to status `0x01`, logout to
`0x02`, and a CMS `0x8702` request returns the current driver state. The DRV1
display name is ASCII-normalized for the JT808 GBK-compatible string field;
the license is padded to the required 20 bytes. Issuing organization and
certificate expiry remain empty because DRV1 does not provide them. Web Config
shows the current driver state, name, license and report ACK state without
restarting the camera pipeline.

Not implemented: audio, talkback, download, alarm video, multimedia snapshot
upload
upload, UDP media and H.265 JT1078.
